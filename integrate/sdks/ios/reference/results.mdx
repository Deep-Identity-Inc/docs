Every view calls `onResult` exactly once, with a `Result<…, DeepIDVError>`.

## Confidence scales

Scales differ by result. The SDK passes them through unchanged.

| Field | Scale |
|---|---|
| `DocumentScanResult.confidence` | **0 to 1** |
| `IdentityVerifyResult.overallConfidence`, `.document.confidence`, `.faceDetection.confidence`, `.faceMatch.confidence`, `.faceMatch.threshold` | 0 to 100 |
| `FaceLivenessResult.confidence` | 0 to 100 (`nil` on a failed workflow attempt) |
| `FaceProbe.widthRatio`, `.centerOffset` | 0 to 1 (geometry, not confidence) |

Workflow results expose no scores or thresholds. Read them on your backend from [Retrieve session](/api-reference/sessions/retrieve-session).

## Open sets

These types are structs or tolerant enums, so a newer server can send a value this SDK version doesn't know. Always keep a `default` branch.

- `SessionStatus`, `APIErrorCode`, `WorkflowFailure.Code`, `WorkflowSessionFailure.Code`
- `AntiCheatResult.Verdict` and `.Action`, `IPCheckResult.Verdict`: unknown values arrive as `.unknown(String)`
- `DeepIDVError.Kind`: may gain cases
