---
title: Retrieve Workflow
description: Retrieve a workflow by ID
api: GET /v1/workflows/{id}
---

```
GET /v1/workflows/{id}
```

Returns the full workflow record for the given ID. The workflow must belong to your organization.

## Request

### Headers

| Header | Required | Description |
|--------|----------|-------------|
| `x-api-key` | Yes | Your API key |

### Path parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | string | Yes | The workflow ID |

### Example request

## Response

### 200 — Success

### Workflow object

| Field | Type | Description |
|-------|------|-------------|
| `workflow` | object | The workflow record |
| `workflow.id` | string | Unique workflow identifier |
| `workflow.name` | string | Workflow name |
| `workflow.organization_id` | string | Owning organization ID |
| `workflow.status` | string | `active` or `inactive` |
| `workflow.created_at` | string | ISO 8601 creation timestamp |
| `workflow.updated_at` | string | ISO 8601 last-updated timestamp |
| `workflow.steps` | array | Ordered list of verification steps |
| `workflow.failure_settings` | object \| null | Retry limit stored on the workflow. `null` means no limit is set (typically older workflows), so applicants can retry without limit |
| `workflow.failure_settings.active` | boolean | Whether the retry limit is enforced |
| `workflow.failure_settings.max_attempts` | integer \| null | Failed attempts allowed before the session fails |

### Step object

| Field | Type | Description |
|-------|------|-------------|
| `steps[].id` | string | Step identifier, the same ID you use when creating a workflow (e.g. `ID_VERIFICATION`, `FACE_LIVENESS`) |
| `steps[].config` | object | Step settings in the same flat format the [Create Workflow](/api-reference/workflows/create-workflow) request uses (e.g. `minimum_age`, `confidence_threshold`) |

Some steps can only be configured in the Admin Console and may appear on workflows you retrieve.

When an applicant reaches `failure_settings.max_attempts` failed attempts, the session fails. To change the retry limit on an existing workflow, use the Admin Console.

<Tip>
  To list sessions associated with a workflow, use the [List Sessions](/api-reference/sessions/list-sessions) endpoint with the `workflow_id` query parameter.
</Tip>

### Error responses

| Status | Description |
|--------|-------------|
| `401 Unauthorized` | Missing or invalid API key |
| `403 Forbidden` | Workflow belongs to a different organization |
| `404 Not Found` | No workflow found with the given ID |
| `429 Too Many Requests` | Rate limit exceeded |
